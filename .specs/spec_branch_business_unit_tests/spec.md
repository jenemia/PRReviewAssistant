## 목적과 범위

PR 요청 화면에서 선택한 브랜치의 기준점 대비 변경을 읽고, 새로 추가되거나 변경된 비즈니스 동작을 NUnit으로 검증한다. 예를 들어 보상 계산, 지급 조건, 이벤트 기간, 상태 전이가 대상이다. 화면 표시와 연결, 에디터 도구, 치트, 생성 코드, 포맷이나 이름만 바뀐 코드는 그 자체로 대상에 포함하지 않는다. Unity 전체 빌드, Unity 런타임 테스트, 프로덕션 코드 수정은 범위 밖이다.

christmas2026 저장 결과에서는 Unity 판정 139개와 처리 상한 초과 129개가 건너뜀으로 집계됐다. 생성 요청 5개는 모두 앱이 권장한 경로가 테스트 경로 정책을 위반해 실행 전에 폐기됐다.

## 구현부

- **선택 커밋에서 작업 시작.** `Sources/PRReviewAssistant/Services/UnitTestVerifier.swift`에서 기존 SHA 및 비교 기준을 검증한 뒤 선택 SHA에서 시작하는 별도 로컬 브랜치를 선택 브랜치와 같은 sprint 하위 `unittest/`에 만들어 임시 Git worktree에 체크아웃한다(예: `sprint/s29/feature/christmas2026` → `sprint/s29/unittest/christmas2026`, sprint 밖이면 `unittest/{이름}`). 같은 이름의 브랜치가 이미 있으면 그 브랜치(원격 우선, 로컬과 갈라지면 중단)를 체크아웃하고 선택 SHA를 병합한 뒤 이어서 진행한다. 이때 이 UnitTest 브랜치가 선택 SHA 위에 추가한 테스트만 같은 경로로 수정하거나 `deletions`로 삭제할 수 있고, 그 밖의 기존 테스트는 보호한다. `ReviewStore.swift`는 분류와 생성 에이전트를 해당 worktree에서 실행한다. 원본 브랜치와 원래 작업 폴더를 보존하고, 작업 종료 시 임시 worktree와 이번에 만든 로컬 브랜치를 정리한다(이미 있던 로컬 브랜치는 유지하고 푸시한 커밋으로만 옮긴다). 검증에 통과한 변경만 체크아웃한 브랜치 끝의 자식 커밋으로 같은 이름의 원격 브랜치에 푸시하며, 그 사이 원격이 바뀌면 푸시하지 않는다.
- **비즈니스 동작을 먼저 선별.** 변경된 C# 소스의 diff를 묶음으로 분류한다. 에이전트는 원본 경로와 구체적인 변경 동작을 반환한다. 앱은 경로를 입력 후보로 제한하며 분류 응답이 유효하지 않으면 생성과 푸시를 중단한다. 중요도 높은 후보부터 기존 최대 5개까지 생성하고, 범위 밖과 상한으로 미처리한 수를 테스트 결과와 구분한다.
- **변경 동작으로 생성 범위 제한.** `CursorAgent.swift`에서 선별된 동작의 입력과 기대 결과를 검증하도록 요청한다. 기존 테스트로 충분히 검증된 변경은 제외할 수 있고, 같은 이름의 테스트가 있어도 커버되지 않은 변경은 새 테스트 파일로 다룬다. 권장 경로와 앱의 테스트 경로 정책은 일치해야 한다.
- **검증 범위.** 임시 NUnit 프로젝트에는 선택 커밋의 전체 대상 소스, 생성된 테스트, 에이전트가 지정한 제한된 수의 동일 커밋 C# 의존 소스를 포함할 수 있다. 프로젝트 전용 패키지나 Unity 런타임 없이는 검증할 수 없는 경우 사유를 표시한다. 실제 검증을 통과한 파일만 반영한다.

## 사이드 이펙트

| 항목 | 영향과 완화 |
|---|---|
| 원본 작업 폴더와 원격 브랜치 | 임시 worktree와 새 원격 브랜치를 사용한다. 원본 SHA가 바뀌면 푸시하지 않는다. |
| 분류 시간과 입력 크기 | 제한된 크기의 diff 묶음으로 분류하고 파일당 입력을 제한한다. 분류와 생성 진행을 분리해 표시한다. |
| 테스트 설치 위치 | 기존 샘플은 스타일 참고로 사용하고, 새 테스트는 기존 파일과 충돌하지 않는 정책 허용 경로에만 기록한다. |
| 분류 정확도 | 에이전트 판정은 프로젝트마다 달라질 수 있다. 실제 브랜치의 선정 결과를 QA에서 점검한다. |

## 테스트 시나리오

| 항목 | 상황 | 기대 결과 |
|---|---|---|
| 선택 커밋에서 작업 시작 | 등록 폴더의 체크아웃이 선택 브랜치와 다름 | 에이전트가 임시 브랜치의 선택 SHA를 읽고, 등록 폴더의 HEAD와 파일은 보존된다. |
| 기존 UnitTest 브랜치 이어서 진행 | 이전 실행이 `unittest/…`를 푸시한 뒤 선택 브랜치에 새 커밋이 생김 | 기존 브랜치에 새 커밋을 병합하고, 이전 테스트를 수정·삭제한 커밋을 같은 브랜치에 푸시한다. 프로젝트 기존 테스트 삭제 제안은 폐기된다. |
| 비즈니스 동작을 먼저 선별 | UI와 보상 규칙 변경이 섞여 있음 | 분류된 보상 규칙만 생성 대상으로 전달되고, 상한 초과와 범위 밖은 별도 집계된다. |
| 변경 동작으로 생성 범위 제한 | 가까운 테스트가 정책 경로 밖이거나 동명 테스트가 있음 | 정책을 만족하는 신규 경로가 제안되며 기존 파일은 보존된다. |
| 검증 범위 | 대상 소스가 동일 커밋의 보조 타입을 참조함 | 검증 입력으로 해당 소스를 제공할 수 있고, 통과한 테스트만 푸시한다. |
| 검증 실패 회귀 | 제안 오류 또는 테스트 실패 | 기존 재시도 정책을 따르고 실패한 파일은 푸시하지 않는다. |

## 미결

- 개발 범위는 위 구현부를 따른다.
- 기획 범위 밖 추가 작업은 없다.
- QA에서는 christmas2026 실브랜치에서 분류 결과와 실행 여부를 확인한다.
