## 목적과 범위

PR 요청 화면에서 선택한 브랜치의 기준점 대비 변경을 읽고, 새로 추가되거나 변경된 비즈니스 동작을 NUnit으로 검증한다. 예를 들어 보상 계산, 지급 조건, 이벤트 기간, 상태 전이가 대상이다. 화면 표시와 연결, 에디터 도구, 치트, 생성 코드, 포맷이나 이름만 바뀐 코드는 그 자체로 대상에 포함하지 않는다. Unity 전체 빌드, Unity 런타임 테스트, 프로덕션 코드 수정은 범위 밖이다.

christmas2026 저장 결과에서는 Unity 판정 139개와 처리 상한 초과 129개가 건너뜀으로 집계됐다. 생성 요청 5개는 모두 앱이 권장한 경로가 테스트 경로 정책을 위반해 실행 전에 폐기됐다.

## 구현부

- **등록 폴더의 로컬 UnitTest 브랜치에서 작업.** `Sources/PRReviewAssistant/Services/UnitTestVerifier.swift`에서 기존 SHA 및 비교 기준을 검증한 뒤, 등록 폴더를 선택 브랜치와 같은 sprint 하위 `unittest/` 로컬 브랜치로 전환한다(예: `sprint/s29/feature/christmas2026` → `sprint/s29/unittest/christmas2026`, sprint 밖이면 `unittest/{이름}`). 브랜치가 없으면 선택 SHA에서 만들고, 로컬 또는 원격에 있으면 그 브랜치를 체크아웃한다. 추적 파일에 커밋하지 않은 변경이 있으면 그 파일만 `git stash`로 임시 보관하고 전환하며, 테스트를 쓴 뒤(실패로 끝나도) UnitTest 브랜치에서 `git stash pop`으로 다시 적용한다. 다시 적용이 충돌하면 stash 항목을 남기고 결과 요약에 알린다. 추적하지 않는 파일은 전환을 막지 않으며, 생성 테스트가 같은 경로의 사용자 파일을 덮어쓰지 않는다. 이미 그 UnitTest 브랜치이고 남은 변경이 이전 실행의 테스트 파일뿐이면 이어서 진행한다. 기존 UnitTest 브랜치가 선택 SHA보다 뒤처져 있기만 하면 fast-forward로 옮기고(커밋 없음), 선택 SHA에 없는 커밋이 있어 갈라졌으면 병합 커밋을 만들지 않기 위해 전환 전에 중단한다. 분류와 생성 에이전트는 등록 폴더에서 읽기 전용으로 실행한다. 검증은 임시 NUnit 프로젝트에서 하고, 통과한 테스트는 등록 폴더의 작업 트리에 쓰거나 지운다. 커밋과 푸시는 하지 않으며 작업이 끝나도 UnitTest 브랜치에 남는다. 이 UnitTest 브랜치가 선택 SHA 위에 추가한 테스트와 이전 실행이 남긴 커밋 전 테스트만 같은 경로로 수정하거나 `deletions`로 삭제할 수 있고, 그 밖의 기존 테스트는 보호한다.
- **브랜치 자신의 변경만 비교.** PR 제안 base가 없으면 `sprint/sNN/...` 브랜치는 원격 `sprint/sNN/main`을, 그 밖에는 저장소 기본 브랜치를 비교 기준으로 쓴다(브랜치 리뷰도 같은 기준). 비교 범위에서 이 브랜치의 first-parent 비병합 커밋이 건드리지 않은 파일은 다른 브랜치 병합으로 들어온 변경으로 보고 선별 전에 제외한다. 결과 요약에 기준과 병합 유입 제외 수를 표시한다. christmas2026은 `origin/main` 기준 328개였고, `sprint/s29/main` 기준 15개다.
- **비즈니스 동작을 먼저 선별.** 변경된 C# 소스의 diff와 파일별 이 브랜치 커밋 메시지를 묶음으로 분류한다. 선별 기준은 `unittest-target-selection` 스킬과 프롬프트에 둔다: 입력이 정해지면 결과가 정해지는 결정 로직(자격·조건, 수치 계산, 기간, 상태 전이, 데이터 변환)만 고르고 behavior에 `진입점: 조건 → 결과` 규칙을 쓴다. UI·연출·리소스·리팩터링은 제외하고, Unity 의존이어도 결정 로직이 있으면 후보로 둔다. 에이전트는 원본 경로와 구체적인 변경 동작을 반환한다. 앱은 경로를 입력 후보로 제한하며 분류 응답이 유효하지 않으면 생성과 푸시를 중단한다. 중요도 높은 후보부터 기존 최대 5개까지 생성하고, 범위 밖과 상한으로 미처리한 수를 테스트 결과와 구분한다.
- **변경 동작으로 생성 범위 제한.** `CursorAgent.swift`에서 선별된 동작의 입력과 기대 결과를 검증하도록 요청한다. 기존 테스트로 충분히 검증된 변경은 제외할 수 있고, 같은 이름의 테스트가 있어도 커버되지 않은 변경은 새 테스트 파일로 다룬다. 권장 경로와 앱의 테스트 경로 정책은 일치해야 한다.
- **테스트 방법론 지침.** 생성 프롬프트와 기본 UnitTest 스킬에 C#·게임 테스트 자료(Khorikov, Osherove, Microsoft Learn .NET 테스트 권장사항, Unity Test Framework 문서, Unity Humble Object 글, Game Programming Patterns)에서 뽑은 규칙을 둔다. 결과값 검증 우선, 내부 호출 검증과 mock 금지, Act 하나, 테스트 안 분기 금지, 단순 getter 제외, 시간·난수 주입 경로만 검증, 확률 경계의 결정적 검증, .5 반올림 고정이다. 확률·가챠·상태 전이용 `unittest-domain-probability` 스킬을 기본 스킬에 추가한다. 기본 스킬은 없을 때만 설치하므로 이미 설치한 사용자는 설정에서 기존 파일을 지우고 다시 설치해야 새 내용을 받는다.
- **비즈니스 모델 추출.** 생성 에이전트는 테스트를 쓰기 전에 diff의 규칙을 `입력·조건 → 기대 결과` 단위로 `businessRules`(id, rule, source)에 반환한다. source는 기대값 출처(spec, diff, code)다. 테스트를 만들지 못한 판정에도 규칙을 반환하고, 앱은 파일별 결과에 "추출한 비즈니스 규칙"으로 보여 준다.
- **원본 직접 호출 우선, 안 되면 원본 로직 복제.** 생성 에이전트는 public 또는 public static API로 규칙을 호출할 수 있으면 원본을 직접 호출한다(`verification: "source"`). 원본이 컴파일되지 않거나(TMPro, UI) 인스턴스·싱글톤·서버 시각에 묶이면 규칙 부분을 테스트 파일 안 private 중첩 클래스로 그대로 옮기고 엔진·시간 값을 인자로 바꿔 검증한다(`verification: "replica"`). 복제 테스트는 대상 소스를 컴파일하지 않으며, 옮긴 로직에 `// 원본: <경로>` 표시가 없으면 다시 요청한다. 결과에는 "원본 로직 복제 검증"으로 표시한다. 옮길 결정 로직이 없을 때만 생성 불가로 보고한다.
- **Unity 고유 코드 검증.** 추적 파일에 `ProjectSettings/ProjectVersion.txt`가 있으면 Unity 프로젝트로 보고, 검증 프로젝트에 `UnityEngineShim.swift`의 UnityEngine 대체 소스와 C# 9 고정(`Directory.Build.props`)을 넣는다. 테스트에서 `UnityEngine`을 쓸 수 있고 `UnityEditor`와 대체 소스 내부 이름은 계속 금지한다. 대체 소스의 Mathf, Vector2/3, Vector2Int/3Int, Inspector 특성, `ScriptableObject.CreateInstance`(Awake·OnEnable 호출)는 실제 Unity와 같은 결과를 낸다. MonoBehaviour·GameObject·Transform 멤버, Time, Random, PlayerPrefs 등 엔진 전용 API는 컴파일만 되고, 실행하면 예외를 잡더라도 그 테스트를 실패시킨다. 예상하지 않은 `Debug.LogError`도 Unity처럼 실패다. 그래서 MonoBehaviour 안의 static 규칙과 ScriptableObject 설정 로직을 검증할 수 있고, 스텁에서만 통과하는 테스트는 반영하지 않는다.
- **검증 범위.** 임시 NUnit 프로젝트에는 선택 커밋의 전체 대상 소스, 생성된 테스트, 에이전트가 지정한 제한된 수의 동일 커밋 C# 의존 소스를 포함할 수 있다. 프로젝트 전용 패키지나 Unity 런타임 없이는 검증할 수 없는 경우 사유를 표시한다. 실제 검증을 통과한 파일만 반영한다.

## 사이드 이펙트

| 항목 | 영향과 완화 |
|---|---|
| 등록 폴더와 원격 브랜치 | 등록 폴더가 로컬 UnitTest 브랜치로 전환되어 열려 있는 Unity 에디터가 다시 가져오기를 할 수 있다. 커밋하지 않은 변경은 stash로 보관했다가 UnitTest 브랜치에서 다시 적용한다. 커밋·푸시하지 않으므로 원격은 바뀌지 않는다. |
| 분류 시간과 입력 크기 | 제한된 크기의 diff 묶음으로 분류하고 파일당 입력을 제한한다. 분류와 생성 진행을 분리해 표시한다. |
| 테스트 설치 위치 | 기존 샘플은 스타일 참고로 사용하고, 새 테스트는 기존 파일과 충돌하지 않는 정책 허용 경로에만 기록한다. |
| 분류 정확도 | 에이전트 판정은 프로젝트마다 달라질 수 있다. 실제 브랜치의 선정 결과를 QA에서 점검한다. |

## 테스트 시나리오

| 항목 | 상황 | 기대 결과 |
|---|---|---|
| 로컬 UnitTest 브랜치에서 작업 | 등록 폴더가 깨끗하고 다른 브랜치에 있음 | 선택 SHA에서 만든 로컬 UnitTest 브랜치로 전환되고, 통과한 테스트 파일이 커밋 없이 남는다. |
| 로컬 UnitTest 브랜치에서 작업 | 추적 파일에 커밋하지 않은 사용자 변경이 있음 | stash로 보관하고 전환한 뒤, 테스트를 쓰고 UnitTest 브랜치에서 다시 적용한다. 실패로 끝나도 다시 적용한다. |
| 로컬 UnitTest 브랜치에서 작업 | 추적하지 않는 폴더(예: `.worktrees/`)가 있음 | 전환하고 진행하며 그 파일은 그대로 남는다. |
| 기존 UnitTest 브랜치 이어서 진행 | 이전 실행이 남긴 커밋 전 테스트가 있음 | 같은 경로로 수정하거나 삭제한다. 프로젝트 기존 테스트 삭제 제안은 폐기된다. 기존 UnitTest 브랜치가 뒤처져 있으면 커밋 없이 앞당기고, 갈라져 있으면 전환 전에 중단한다. |
| 비즈니스 동작을 먼저 선별 | UI와 보상 규칙 변경이 섞여 있음 | 분류된 보상 규칙만 생성 대상으로 전달되고, 상한 초과와 범위 밖은 별도 집계된다. |
| 변경 동작으로 생성 범위 제한 | 가까운 테스트가 정책 경로 밖이거나 동명 테스트가 있음 | 정책을 만족하는 신규 경로가 제안되며 기존 파일은 보존된다. |
| 검증 범위 | 대상 소스가 동일 커밋의 보조 타입을 참조함 | 검증 입력으로 해당 소스를 제공할 수 있고, 통과한 테스트만 작업 트리에 쓴다. |
| 검증 실패 회귀 | 제안 오류 또는 테스트 실패 | 기존 재시도 정책을 따르고 실패한 파일은 쓰지 않는다. |
| 비즈니스 모델 추출 | 생성 불가(Unity 의존) 판정 | 파일 결과에 추출한 규칙이 남는다. |
| 브랜치 자신의 변경만 비교 | sprint 브랜치가 다른 브랜치를 병합함 | 기준은 `sprint/sNN/main`이고 병합으로만 들어온 파일은 선별에 전달되지 않는다. |
| 원본 로직 복제 | 대상이 TMPro를 참조하는 MonoBehaviour | 복제 테스트만 컴파일·실행해 통과하면 작업 트리에 쓰고 "원본 로직 복제 검증"으로 표시한다. 원본 표시가 없으면 다시 요청한다. |
| Unity 고유 코드 검증 | MonoBehaviour static 계산, ScriptableObject 기본값, Vector3 비교 | 대체 소스로 컴파일·실행되어 통과한다. |
| Unity 고유 코드 검증 | 테스트가 `Time.deltaTime` 예외를 잡거나 LogError 경로를 통과로 다룸 | 해당 테스트가 실패해 반영되지 않는다. |

## 미결

- 개발 범위는 위 구현부를 따른다.
- 기획 범위 밖 추가 작업은 없다.
- QA에서는 christmas2026 실브랜치에서 분류 결과와 실행 여부를 확인한다.
- 대체 소스에 없는 UnityEngine API(UI, TMPro, Addressables 등)를 쓰는 파일은 여전히 Unity 의존으로 건너뛴다. 실제 엔진 검증이 필요하면 Unity CLI `-batchmode -runTests -testPlatform EditMode`로 최종 확인하는 단계를 후속으로 검토한다(에디터 설치·라이선스 필요, 같은 프로젝트가 에디터에 열려 있으면 실행 불가).
