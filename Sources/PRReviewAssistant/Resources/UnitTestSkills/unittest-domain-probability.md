# 확률·상태 전이 로직 테스트 기준

## 반드시 넣을 케이스 (결정적)
- **가중치 경계**: 가중치 0인 항목은 절대 뽑히지 않고, 하나만 0보다 크면 항상 그 항목이 나온다.
- **확률 경계**: 0%는 실패, 100%는 성공. 난수 값을 인자로 받는다면 경계 값(0, 합계-1, 합계)을 직접 넣어 어떤 항목이 선택되는지 고정한다.
- **천장(pity)**: 천장 직전 회차와 천장 회차, 천장 이후 카운터 초기화.
- **합계 불변식**: 확률표 합계가 100%(또는 가중치 합 > 0)가 아니면 예외인지 보정인지 Spec대로 고정한다.

## 난수 다루는 법
- 시드 없는 무작위 결과에 assert하지 않는다. `System.Random(seed)`나 주입된 난수 함수가 있을 때만 사용한다.
- `UnityEngine.Random`을 내부에서 직접 읽으면 원본을 그대로 호출해 검증하지 않는다. 원본 로직 복제에서 난수 값을 인자로 바꿔 경계를 검증한다 (분리 제안은 reason에 적는다).
- 분포 검증이 꼭 필요하면 고정 시드, 충분한 시행 수(예: 10,000회), 허용 오차를 둔 범위 비교만 쓴다. 표본이 작은 분포 테스트는 만들지 않는다.

## 상태 전이
- 허용된 전이마다 이전 상태 → 이벤트 → 다음 상태를 한 케이스로 쓴다.
- 허용되지 않은 전이는 상태가 그대로인지(또는 Spec대로 예외인지) 확인한다.
- 같은 이벤트를 두 번 보냈을 때(중복 지급, 중복 수령) 결과가 한 번만 반영되는지 확인한다.

## Spec 확인 항목
- 확률표·천장 수치는 Spec의 조절 수치 표 값을 기대값으로 쓴다. 코드 상수를 참조해 기대값을 계산하지 않는다.
