# 재화 로직 테스트 기준

## 반드시 넣을 케이스
- **0과 음수**: 가격 0, 음수 입력(보정되는지 예외인지는 Spec대로 고정).
- **하한/상한**: 할인 후 가격이 0 아래로 내려가지 않는지, 보유 한도가 있다면 한도 직전·정확히 한도·한도 초과.
- **반올림/절사**: 소수점이 생기는 값(예: 15의 85%)으로 절사인지 반올림인지를 구체적인 값으로 고정. 정수 나눗셈은 곱셈 후 나눗셈 순서도 확인한다.
- **오버플로**: `int` 곱셈이 넘칠 수 있는 큰 값 (예: `int.MaxValue` 근처). Spec에 처리 방식이 없으면 기대값을 단정하지 말고 `assumptions`에 적는다.
- **차감**: 잔액 부족 시 실패하고 **잔액이 그대로인지**, 정확히 잔액만큼 차감하면 0이 되는지.
- **등급/조건 분기**: 조건이 참인 경우와 거짓인 경우를 둘 다 (예: VIP / 일반).

## 값 고정 방식
- 비율·수치는 Spec의 조절 수치 표 값을 그대로 기대값으로 쓴다. 코드 상수를 테스트에서 참조해 기대값을 계산하지 않는다 (상수가 바뀌어도 테스트가 따라가 버린다).
- 결과가 통화 단위로 정수여야 하면 `Assert.AreEqual(정수, ...)`로 비교한다. `double` 비교가 필요할 때만 허용 오차를 쓴다.

## Spec 확인 항목
- 음수 입력 시 예외인지 보정인지, 반올림 규칙, 상한 존재 여부가 Spec에 없으면 `assumptions`에 적고 불확실한 케이스는 만들지 않는다.
