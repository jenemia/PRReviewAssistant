# 시간·시즌 로직 테스트 기준

## 반드시 넣을 케이스
- **주기 경계**: 주기의 마지막(예: 7일째)과 바로 다음(8일째 = 1일째로 돌아옴).
- **시작/끝 경계**: 기간의 시작 시각 직전·정각·직후, 끝 시각 직전·정각·직후. 시작/끝이 포함인지 미포함인지는 Spec 문구대로 고정한다.
- **리셋 시각**: 리셋 직전과 직후 (자정, 주간/시즌 리셋).
- **잘못된 입력**: 0 이하 일수, 시작 > 끝, 음수 기간.
- **여러 주기 뒤**: 주기의 배수 이상 큰 값 (예: 15일째).

## 시간 다루는 법
- 테스트 안에서 `DateTime.Now`/`UtcNow`를 쓰지 않는다. 고정된 날짜를 직접 만든다 (`new DateTime(2026, 1, 1, 0, 0, 0, DateTimeKind.Utc)`).
- 대상 코드가 현재 시각을 내부에서 읽으면 시각을 바꿀 수 없다. 이때는 억지로 테스트하지 말고 `needs_source_change`로 보고한다 (시각을 인자로 받도록 바꾸는 제안은 보고에만 적는다).
- 타임존·`DateTimeKind`가 결과에 영향을 주면 Utc 고정 입력으로 검증하고, 지역 시간 의존은 가정으로 적는다.

## Spec 확인 항목
- 일차가 1부터인지 0부터인지, 주기 마지막 날의 특별 규칙이 있는지를 코드가 아니라 Spec에서 확인한다.
